Sonarly connects to Grafana using a service account token to receive alerts and query your Prometheus metrics and Loki logs during investigation.

## Connect Grafana

<Steps>
  <Step title="Create a service account">
    In Grafana, go to **Administration** → **Service accounts** → **Add service account**. Give it the **Viewer** role and the **Data sources: Explorer** fixed role.
  </Step>
  <Step title="Generate a token">
    Create a token for the service account and copy it.
  </Step>
  <Step title="Enter credentials">
    On the Sonarly onboarding page, enter your Grafana URL and the service account token.
  </Step>
  <Step title="Auto-setup">
    Sonarly validates access, discovers your datasources, and auto-creates a **Sonarly** webhook contact point in Grafana. A route is added to your notification policy with `continue: true` so your existing alert routing is not affected.
  </Step>
</Steps>

## How it works

When a Grafana alert fires:

1. Grafana sends the alert to the Sonarly contact point
2. Sonarly deduplicates against recent alerts (15-minute window)
3. Claude Code investigates using your Grafana data:
   - Queries **Prometheus** metrics via PromQL
   - Searches **Loki logs** with LogQL
   - Inspects **dashboards** and panel queries
   - Checks **annotations** for recent deploys
   - Searches **Tempo traces** for errors
   - Analyzes your **codebase** for the root cause
4. An incident report is generated with root cause and fix

## Observability tools available to the AI

| Tool | What it does |
|------|-------------|
| **grafana_query_metrics** | Run PromQL queries against Prometheus |
| **grafana_query_logs** | Search logs with LogQL (raw, patterns, or aggregation) |
| **grafana_aggregate_logs** | Aggregate logs with LogQL metric queries (count_over_time, rate, etc.) |
| **grafana_query_traces** | Search Tempo traces by service, duration, status |
| **grafana_query_alerts** | List active alert rules and their states |
| **grafana_query_annotations** | Check deploy markers and alert state changes |
| **grafana_query_slos** | Query SLO definitions and burn rate |
| **grafana_query_rum** | Query frontend RUM data (if Faro is configured) |
| **grafana_search_dashboards** | Find relevant dashboards by name or tag |
| **grafana_get_dashboard_summary** | Get dashboard overview with panel descriptions |
| **grafana_get_dashboard_panel_queries** | Extract exact queries from dashboard panels |

<Info>
Your service account token never leaves the Sonarly backend. All Grafana queries go through a server-side proxy.
</Info>

## Permissions needed

The service account requires two roles:

| Role | Purpose |
|------|---------|
| **Viewer** | Read access to dashboards, alert rules, and annotations |
| **Data sources: Explorer** (fixed role) | Query Prometheus, Loki, and Tempo via the datasource proxy API |

For automatic webhook setup, the service account also needs:

| Permission | Purpose |
|-----------|---------|
| `alert.provisioning:write` | Create the Sonarly webhook contact point and notification route |

<Tip>
Alternatively, you can assign the **Editor** role (which includes all the above). If your service account lacks provisioning permissions, Sonarly will guide you through manual webhook setup instead.
</Tip>

Sonarly auto-detects which datasources are available (Loki, Tempo, Prometheus) and only enables the corresponding tools. Dashboard tools (`grafana_search_dashboards`, `grafana_get_dashboard_summary`, `grafana_get_dashboard_panel_queries`) are always available regardless of datasources.
