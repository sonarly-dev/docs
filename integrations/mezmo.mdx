Sonarly connects to Mezmo (formerly LogDNA) to query your logs during incident investigation and receive alert webhooks.

## Connect Mezmo

<Steps>
  <Step title="Get your API key">
    In Mezmo, go to **Settings** → **Organization** → **API Keys**. Copy your Service Key.
  </Step>
  <Step title="Enter credentials">
    On the Sonarly settings page, enter your Mezmo API key.
  </Step>
  <Step title="Validation">
    Sonarly validates access by querying your logs.
  </Step>
</Steps>

## Observability tools available to the AI

| Tool | What it does |
|------|-------------|
| **mezmo_search_logs** | Search logs by query, timeframe, level, with patterns view (drain3 clustering) |
| **mezmo_aggregate_logs** | Aggregate log counts grouped by level, host, or app |
| **mezmo_list_views** | List saved views and alerts |
| **mezmo_get_logs_by_host** | Get logs filtered by specific host |
| **mezmo_get_logs_around_time** | Get logs in a window around a specific timestamp |
| **mezmo_get_log_stats** | Get log volume statistics |

<Info>
Your Mezmo API key never leaves the Sonarly backend. All log queries go through a server-side proxy.
</Info>

## Permissions needed

| Credential | Purpose |
|-----------|---------|
| **Service Key** | Authenticates all API requests (read-only log access) |

The Service Key is found in **Settings** → **Organization** → **API Keys**. It grants read-only access to the Mezmo Export API, which Sonarly uses to query your logs. Sonarly never modifies your Mezmo data.

## Webhook alerts

Mezmo can send alert webhooks to Sonarly when log patterns match your alert rules:

```
https://sonarly.dev/api/webhooks/mezmo?tenant_id=YOUR_TENANT_ID
```

Configure this URL as a webhook destination in your Mezmo alert settings.
