Sonarly connects to GitLab via OAuth to access your repositories, analyze your code, and create merge requests with fixes.

## Connect GitLab

<Steps>
  <Step title="Authorize">
    Click **Connect GitLab** from the onboarding page or Settings. Authorize Sonarly with your GitLab account.
  </Step>
  <Step title="Select repositories">
    Choose which repositories Sonarly can access.
  </Step>
  <Step title="Done">
    Sonarly can now clone your repos, analyze code, and create MRs.
  </Step>
</Steps>

## Self-hosted GitLab

Sonarly supports self-hosted GitLab instances. During setup, enter your GitLab instance URL (e.g. `https://gitlab.mycompany.com`) instead of using gitlab.com.

## What Sonarly does with GitLab access

- **Clone repositories** into isolated sandboxes for code analysis
- **Create merge requests** with fixes, root cause analysis, and git blame
- **Auto-remove source branch** after MR is merged

## Permissions

Sonarly requests the `api` OAuth scope, which grants read/write access to the GitLab API. This is needed to:

| Capability | Why |
|-----------|-----|
| **Read repositories** | Clone code for analysis |
| **Create branches** | Push fix branches |
| **Create merge requests** | Open MRs with fixes and root cause analysis |
| **Read user info** | Identify the connected account |

<Info>
Repository access is scoped to the repositories you select during setup. Sonarly never accesses repos you haven't explicitly granted.
</Info>

## Token management

Sonarly uses standard OAuth 2.0 with 2-hour token expiry. Tokens are encrypted at rest and refreshed automatically before expiry. You can disconnect GitLab at any time from Settings.
