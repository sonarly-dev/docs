Sonarly connects to Datadog using API keys to receive alert webhooks and query your logs, traces, and metrics during incident investigation.

## Connect Datadog

<Steps>
  <Step title="Get your API keys">
    In Datadog, go to **Organization Settings** → **API Keys** and **Application Keys**. You need both an API Key and an Application Key.
  </Step>
  <Step title="Enter credentials">
    On the Sonarly onboarding page, enter your API Key, Application Key, and Datadog site (e.g. `us5.datadoghq.com`).
  </Step>
  <Step title="Validation">
    Sonarly validates your credentials and detects which capabilities are available (logs, traces, metrics, monitors, events, SLOs, RUM).
  </Step>
  <Step title="Auto-setup">
    A webhook is automatically created in your Datadog account pointing to Sonarly. No manual configuration needed.
  </Step>
</Steps>

## How it works

When a Datadog alert fires:

1. Datadog sends a webhook to Sonarly with alert details
2. Sonarly deduplicates against recent alerts (15-minute window)
3. Claude Code investigates the incident:
   - Queries your **Datadog logs** around the alert time
   - Checks **monitors** and **metrics** for anomalies
   - Searches **APM traces** for errors
   - Reviews **events** and **SLOs** for context
   - Analyzes your **codebase** for the root cause
4. A detailed incident report is generated with timeline, root cause, and suggested fix
5. If a code fix is identified, a PR is created automatically

## Observability tools available to the AI

During investigation, the AI agent has access to your Datadog data via 8 secure server-side tools:

| Tool | What it does |
|------|-------------|
| **dd_query_logs** | Search logs by query, timeframe, and service |
| **dd_aggregate_logs** | Aggregate logs with timeseries and groupBy |
| **dd_query_traces** | Search APM spans by service, duration, and status |
| **dd_query_metrics** | Query timeseries metrics |
| **dd_query_monitors** | List active monitors and their status |
| **dd_query_events** | Query monitor alert events |
| **dd_query_slos** | List SLOs and their status/history |
| **dd_query_rum** | Search Real User Monitoring data |

<Info>
Your API keys never leave the Sonarly backend. The AI agent queries Datadog through Sonarly's server-side proxy — keys are never exposed in sandboxes or logs.
</Info>

## Permissions needed

| Key | Purpose |
|-----|---------|
| **API Key** | Authenticates all API requests to Datadog |
| **Application Key** | Scopes access — the user who creates it must have the required permissions |

The Datadog user who creates the Application Key needs these permissions in their Datadog role:

| Permission | Purpose |
|-----------|---------|
| **Logs Read Data** | Query logs during incident investigation |
| **Monitors Read** | List monitors and their alert states |
| **APM Traces Read** | Search APM spans and traces |
| **Events Read** | Query monitor alert events |
| **SLO Read** | List SLOs and compliance history |
| **RUM Read** | Query Real User Monitoring data (if applicable) |

For automatic webhook setup, the Application Key also needs:

| Scope | Purpose |
|-------|---------|
| `create_webhooks` | Auto-create the Sonarly webhook in your Datadog account |
| `monitor_config_policy_write` | Auto-create a notification rule to route alerts to the webhook |

<Tip>
If your Application Key doesn't have webhook creation scopes, Sonarly will still work — you'll just need to [create the webhook manually](https://docs.datadoghq.com/integrations/webhooks/) in Datadog pointing to your Sonarly webhook URL.
</Tip>
