Sonarly connects to SigNoz using an API key to receive alerts and query your logs, traces, metrics, and service data during investigation.

## Connect SigNoz

<Steps>
  <Step title="Get your API key">
    In SigNoz, go to **Settings** → **General** → copy your API key. An Admin role is recommended for automatic webhook setup.
  </Step>
  <Step title="Enter credentials">
    On the Sonarly onboarding page, enter your SigNoz URL and API key.
  </Step>
  <Step title="Validation">
    Sonarly validates access by checking the health endpoint, listing services, and running a test log query.
  </Step>
  <Step title="Auto-setup">
    A **Sonarly** webhook notification channel is automatically created in SigNoz. If your API key has Viewer permissions only, you'll get manual setup instructions instead.
  </Step>
</Steps>

## Observability tools available to the AI

| Tool | What it does |
|------|-------------|
| **signoz_search_logs** | Query logs via builder API with filters, patterns view (drain3 clustering), and absolute timestamps |
| **signoz_aggregate_logs** | Aggregate logs with builder API operators (count, avg, p99, rate, etc.) with groupBy |
| **signoz_search_traces** | Search spans by service, operation, duration, status, HTTP method |
| **signoz_query_metrics** | Run PromQL queries for OpenTelemetry metrics |
| **signoz_list_services** | Discover services reporting to SigNoz |
| **signoz_get_service_overview** | Error rate, latency (p50/p90/p99), and throughput for a service |
| **signoz_list_alerts** | List alert rules and their state |
| **signoz_get_alert_history** | Firing history for a specific alert rule |

<Info>
Your API key never leaves the Sonarly backend. All SigNoz queries go through a server-side proxy.
</Info>

## Permissions needed

| Role | What it enables |
|------|----------------|
| **Admin** (recommended) | Read access to all data + automatic webhook creation |
| **Viewer** | Read-only access to logs, traces, metrics, alerts — manual webhook setup required |

The Admin role is recommended because it allows Sonarly to automatically create a webhook notification channel in SigNoz. With Viewer, you'll need to manually add the webhook URL in SigNoz's **Settings** → **Alert Channels**:

```
https://sonarly.dev/api/webhooks/signoz?tenant_id=YOUR_TENANT_ID
```
